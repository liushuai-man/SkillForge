# SkillForge 版本管理器 · 两人分工与交付计划

> **说明**：两人各负责一条工作线，本文档分为两块，各自独立可读。
> **开发周期**：2026 年 10 月 4 日 – 11 月 1 日（4 周，最晚交付 11 月 1 日）
> **共同验收**：改一次 Skill → 不做任何版本操作 → 看到一份语义级对比报告 → 可打锚点 → 可撤销。
> **状态说明**：本文是目标排期，不代表任务已完成。MVP 范围以设计文档 §8.1 为唯一清单；具体用例见[实现契约与验收](./SkillForge%20版本管理器实现契约与验收.md)。本次整理不改日期，不以增加未来功能替代闭环验收。

## 共同交付门槛（两线先读）

| 门槛 | 进入下一阶段需要的证据 | 不能代替证据的东西 |
| --- | --- | --- |
| G0：契约可交接（第 1 周） | Revision/引用/对象读取、报告最小模型、错误/事件规则和正常/失败样例由提供方与消费方核对；语义质量样例初版 | 只有目录、占位函数、未校验的手写 JSON |
| G1：快照可信（第 2 周） | 稳定保存、无变化零写入、A→B→A、原文读回、失败可重试/损坏可检出 | 只在正常路径跑通 init；只检查返回码 |
| G2：核心流程可用（第 3 周） | Web/CLI 使用真实服务完成保存→默认语义报告→锚点→undo；TBD-08/09 已关闭并通过状态样例 | 用 mock 演示整条流程；文档标“已定”但实际协议仍不同 |
| G3：可交付（第 4 周） | 安装包、断网运行、故障恢复、固定样例质量、无缓存重算、平台/性能证据 | 开发机可运行就声称用户免 Node、全平台已验证 |

**前置决策**：TBD-08（undo 文件写回边界）由用户决定；TBD-09（当前状态/Op 的持久化映射）由 A 主责、B 校验。两项状态同步记录在设计 §2.7；未关闭只阻塞相关状态写入/撤销，不阻塞纯 diff 和对象库工作，也不能假报 G2 完成。

**每次交接**：提供方给出模型+样例+相关 AC 结果，消费方用同一 schema 校验；主线检查代码与文档一致性。发现变更先更新权威契约，再更新两侧，不用兼容分支掩盖字段分歧。

**范围控制**：独立导出、CDC、gc/pack、独立结构视图、增强时间线、colocate、模型标签均为后续项，不列入本轮周任务。MVP 保留基础历史列表、待确认标记、报告 JSON 与 M-13 最小类型契约。阻塞时优先关闭依赖门槛，不用开发后续功能制造进度。

# 第一块 · 开发者 A（存储内核线）

> **一句话职责**：把"改一下文件"变成"一个可寻址的快照"，并提供接口与命令行。

## 一、你负责的模块

| 模块 | 名称 | 你要做的事 |
| --- | --- | --- |
| M-01 | 工作区管理 | 绑定 Skill 目录，读写 `workspace.json`（忽略规则、文件类型到解析器的映射） |
| M-02 | 改动监听与快照 | 监听文件保存、500 毫秒合并抖动、内容哈希二次确认、触发快照 |
| M-03 | 对象库与去重 | SHA-256 内容寻址的 blob/tree/meta，原文保真、zlib、完整性；回收后续做 |
| M-04 | 修订与引用 | Revision / Change / Ref 元数据，稳定的 Change ID，revset 表达式解析 |
| M-09 | 操作日志与撤销 | 操作 DAG 记录，`undo`（包括撤销撤销），`restore` 跳转 |
| M-10 | 接口层 | HTTP 路由、参数校验、统一返回 `{ ok, data, error, request_id }`、事件流 |
| M-12 | 命令行客户端 | `start / init / status / snapshot / diff / log / tag / undo / show`；业务命令只调服务 |

## 二、每周要做什么

### 第 1 周｜10 月 4 日 – 10 月 10 日（地基）
- **做**：M-01 工作区纳管；M-03 内容寻址/压缩/两级目录与读回校验；核对现有 DDL；准备公开模型与 B 消费样例。
- **交**：能绑定目录并读回首个对象；初始化失败可重试；对象损坏可识别；完成 G0 中 A 的交接与 TBD-09 方案。
- **验**：AC-01~03、AC-16；已有 DDL 不等于修订/撤销逻辑已经实现。

### 第 2 周｜10 月 11 日 – 10 月 17 日（快照闭环）
- **做**：M-02 监听/静默合并/稳定扫描；M-04 修订、Change 分组与最小 ref 解析；串行提交；落实已关闭的 TBD-09。
- **交**：有限保存突发只提交最终稳定内容；原文不变 0 次业务写盘；A→B→A 记录三次事件且复用内容；提供 B 可读取的真实 Revision 对。
- **验**：AC-04~09、AC-15 的快照故障点；达到 G1。

### 第 3 周｜10 月 18 日 – 10 月 24 日（对比闭环）
- **做**：M-10 真实接口/统一错误/提交后事件；M-12 客户端；M-09 Op/undo；用户打标后选择 Baseline；与 B 联调真实默认报告。
- **交**：默认 diff 输出规范语义报告 JSON；无基线正确回退；锚点与撤销符合已关闭 TBD-08/09 的状态样例。
- **验**：AC-08/09/17/18；不得用文件恢复未定或接口占位宣称 G2 通过。

### 第 4 周｜10 月 25 日 – 11 月 1 日（打磨与交付验收）
- **做**：故障恢复与跨平台边界；端口发现/进程占用；发布包集成预构建前端；安装说明；容量和性能测量。gc/CDC 不在本周补做。
- **交**：可安装包 + 可复现的安装步骤 + 验收记录，明确已测与未测平台；达到 G3。
- **验**：AC-15~20，覆盖断网与终端用户无 Node；不以本机 npm 构建成功代替安装包验证。

## 三、你的验收标准

| 项 | 标准 |
| --- | --- |
| 变更合并 | 有限突发后 500 ms 静默，只提交最终稳定快照；Change 分组另按设计 §7.2 |
| 零写入 | 原始 tree 与当前已提交状态相同：0 新对象/Revision/Op/业务数据库更新 |
| 快照速度 | 保存后 ≤ 2 秒可见"有未纳管改动"；写入（≤ 1 MB）≤ 300 毫秒 |
| 撤销 | TBD-08/09 关闭后的状态样例通过，含撤销撤销；不能以版本库指针变化冒充文件恢复 |
| 存储 | 10000 次保存按唯一对象累计压缩大小测量，无重复对象；变化大文件的完整 blob 写放大单列 |
| 平台 | Windows / macOS / Linux 行为一致 |
| 总验收 | 改一次 Skill → 不做任何版本操作 → 看到对比报告 → 可打锚点 → 可撤销 |

# 第二块 · 开发者 B（对比呈现线）

> **一句话职责**：把两个快照变成"一份看得懂、可复现的对比报告"。

## 一、你负责的模块

| 模块 | 名称 | 你要做的事 |
| --- | --- | --- |
| M-05 | 分层对比引擎 | L0 元信息 / L1 文本 / L2 结构 / L3 语义 四层差异计算与按层缓存 |
| M-06 | 语义抽取器 | 把 Skill 抽成 8 类语义单元：role、capability、constraint、tool、workflow、example、output_format、parameter |
| M-07 | 聚类与降噪 | 折叠格式噪声、聚合同意图改动、打人话标签、标注"待确认" |
| M-08 | 报告与结论 | 规范报告 JSON、模板结论、风险与待确认标记；独立文件导出后续做 |
| M-11 | 对比界面（Web） | 语义/文本两视图、并排与词级高亮、基础历史列表；结构视图/增强时间线后续做 |
| M-13 | 行为对比适配器（预留） | 只定义接口契约，不做任何实现 |

## 二、每周要做什么

### 第 1 周｜10 月 4 日 – 10 月 10 日（地基·预研）
- **做**：L0/L1 原型与原文坐标映射；tree-sitter Markdown/YAML/JSON PoC；固定人工标注样例；与 A 核对 Revision 读取/报告模型。
- **交**：独立文本 diff、解析 PoC 结论、含八类单元/格式/坏语法的样例初版；G0 中 B 的消费样例。
- **验**：AC-07/10/11 的样例与预期先确定，不能等算法实现后反向写答案。

### 第 2 周｜10 月 11 日 – 10 月 17 日（结构与语义）
- **做**：L2 节点增删改移，先精确移动再有证据的相似匹配；L3 八类规则版；逐文件降级；用 A 的真实对象测试。
- **交**：八类样例可跑、否定/流程顺序/示例边界明确；歧义保留待确认，不能把所有重排当噪声。
- **验**：AC-07/10~12；语义质量按聚类前变更计数，单列误报与漏报。

### 第 3 周｜10 月 18 日 – 10 月 24 日（对比闭环）
- **做**：含有效分析配置指纹的缓存；规范报告与证据链；真实服务上的语义/文本页面；规则聚类；旧结果与处理中状态区分。
- **交**：默认 L3 报告自动生成；无基线回退；层状态不混淆；人工标为 ≤5 个意图的 20 处改动聚类 ≤5 组。
- **验**：AC-08~14/17/18；联调达到 G2，不仅展示 mock。

### 第 4 周｜10 月 25 日 – 11 月 1 日（打磨与交付验收）
- **做**：基础历史/两视图体验收尾；规范报告无缓存重算；M-13 最小类型契约（零实现）；质量、性能和前端安装产物验证。
- **交**：规则报告可读取与归档；契约样例 + 质量/性能/平台验收记录；配合 A 达到 G3。独立导出和三视图不扩入本周。
- **验**：AC-10~14/17/19/20；旧报告不被新配置或新算法改写。

## 三、你的验收标准

| 项 | 标准 |
| --- | --- |
| 默认对比 | 打开即得 Working vs Baseline，不需要选择对比对象 |
| 可读性 | 固定人工样例正确识别率 ≥80%（聚类前）；关键否定/顺序/示例用例必须通过，误报单列 |
| 噪声比 | 主结论中纯格式/无语义影响重排条目 ≤10%；纯格式样例不得给出肯定语义结论 |
| 聚类 | 20 处改动且人工意图 ≤5 个时，聚成 ≤5 组；不丢单元、不合并无关意图 |
| 可复现 | 同不可变 Revision 对、layer、有效 algo_version，清缓存重算仍逐字节相同（100%） |
| 性能 | L0 + L1 ≤ 200 毫秒；L2 ≤ 1.5 秒；L3 ≤ 3 秒；缓存命中 ≤ 100 毫秒 |
| 降级 | 按文件回退并注明可用层；对象损坏/I/O 失败不得伪装解析降级或无差异 |
| 总验收 | 改一次 Skill → 不做任何版本操作 → 看到语义级对比报告 → 可打锚点 → 可撤销 |
