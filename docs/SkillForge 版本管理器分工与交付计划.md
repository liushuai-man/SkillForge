# SkillForge 版本管理器 · 两人分工与交付计划

> **说明**：两人各负责一条工作线，本文档分为两块，各自独立可读。
> **开发周期**：2026 年 10 月 4 日 – 11 月 1 日（4 周，最晚交付 11 月 1 日）
> **共同验收**：改一次 Skill → 不做任何版本操作 → 看到一份语义级对比报告 → 可打锚点 → 可撤销。

---

# 第一块 · 开发者 A（存储内核线）

> **一句话职责**：把"改一下文件"变成"一个可寻址的快照"，并提供接口与命令行。

## 一、你负责的模块

| 模块 | 名称 | 你要做的事 |
| --- | --- | --- |
| M-01 | 工作区管理 | 绑定 Skill 目录，读写 `workspace.json`（忽略规则、文件类型到解析器的映射） |
| M-02 | 改动监听与快照 | 监听文件保存、500 毫秒合并抖动、内容哈希二次确认、触发快照 |
| M-03 | 对象库与去重 | SHA-256 内容寻址的 blob / tree 存储，zlib 压缩，引用计数回收 |
| M-04 | 修订与引用 | Revision / Change / Ref 元数据，稳定的 Change ID，revset 表达式解析 |
| M-09 | 操作日志与撤销 | 操作 DAG 记录，`undo`（包括撤销撤销），`restore` 跳转 |
| M-10 | 接口层 | HTTP 路由、参数校验、统一返回 `{ ok, data, error, request_id }`、事件流 |
| M-12 | 命令行客户端 | `init / status / snapshot / diff / log / tag / undo / show / export`，与服务完全等价 |

## 二、每周要做什么

### 第 1 周｜10 月 4 日 – 10 月 10 日（地基）
- **做**：M-01 工作区纳管；M-03 对象库骨架（内容寻址、压缩、两级目录）；SQLite 建表。
- **交**：v0.1 骨架——能绑定一个 Skill 目录并写入第一个对象。

### 第 2 周｜10 月 11 日 – 10 月 17 日（快照闭环）
- **做**：M-02 文件监听 + 抖动合并 + 内容哈希确认 + 快照前全量兜底；M-04 修订模型与 revset 解析。
- **交**：保存即生成快照；连存 5 次只产生 1 个变更；内容不变 0 次写盘。

### 第 3 周｜10 月 18 日 – 10 月 24 日（对比闭环）
- **做**：M-10 接口层（路由、校验、统一返回、事件流）；M-12 命令行客户端；M-09 操作日志与撤销；Baseline 自动前移。
- **交**：`skillforge-vm diff` 默认输出 Working vs Baseline 的完整报告 JSON；撤销与状态跳转可用。

### 第 4 周｜10 月 25 日 – 11 月 1 日（打磨与交付验收）
- **做**：M-03 引用计数回收与 gc；边界场景（内容不变、写盘风暴、CRLF 换行、端口占用、同工作区并发写）；打包发布（pipx + 预构建前端产物，用户免装 Node）；部署文档；非功能验收。
- **交**：可安装包 + 部署文档 + 验收报告。

## 三、你的验收标准

| 项 | 标准 |
| --- | --- |
| 变更合并 | 连存 5 次只产生 1 个变更 |
| 零写入 | 内容不变时 0 次写盘 |
| 快照速度 | 保存后 ≤ 2 秒可见"有未纳管改动"；写入（≤ 1 MB）≤ 300 毫秒 |
| 撤销 | 一键撤销可用，包括"撤销撤销" |
| 存储 | 10000 次快照下，对象库增长与净变化同阶，无重复存储 |
| 平台 | Windows / macOS / Linux 行为一致 |
| 总验收 | 改一次 Skill → 不做任何版本操作 → 看到对比报告 → 可打锚点 → 可撤销 |

# 第二块 · 开发者 B（对比呈现线）

> **一句话职责**：把两个快照变成"一份看得懂、可复现的对比报告"。

## 一、你负责的模块

| 模块 | 名称 | 你要做的事 |
| --- | --- | --- |
| M-05 | 分层对比引擎 | L0 元信息 / L1 文本 / L2 结构 / L3 语义 四层差异计算与按层缓存 |
| M-06 | 语义抽取器 | 把 Skill 抽成 8 类语义单元：role、capability、constraint、tool、workflow、example、output_format、parameter |
| M-07 | 聚类与降噪 | 折叠格式噪声、聚合同意图改动、打人话标签、标注"待确认" |
| M-08 | 报告与结论 | 报告结构、一句话结论（模板生成，不调用大模型）、风险标记、导出 |
| M-11 | 对比界面（Web） | 语义 / 结构 / 文本三视图、并排与行内、词级高亮、时间线 |
| M-13 | 行为对比适配器（预留） | 只定义接口契约，不做任何实现 |

## 二、每周要做什么

### 第 1 周｜10 月 4 日 – 10 月 10 日（地基·预研）
- **做**：M-05 的 L0 / L1 骨架（自研行级 diff + 词级高亮 + CRLF/LF 规范化）；tree-sitter 解析 PoC（Markdown / YAML / JSON）。
- **交**：可独立运行的文本 diff 原型；解析 PoC 结论。

### 第 2 周｜10 月 11 日 – 10 月 17 日（结构与语义）
- **做**：M-05 的 L2 结构树 diff（节点级增 / 删 / 改 / 移）+ 移动与重命名检测；M-06 语义抽取器（8 类单元，规则 + 结构树遍历）。
- **交**：L2 结构 diff 可跑且重排识别为"移动"；L3 规则版跑通全部 8 类单元。

### 第 3 周｜10 月 18 日 – 10 月 24 日（对比闭环）
- **做**：M-05 结果缓存（键含算法版本）；M-08 报告骨架 + 一句话结论模板 + 风险标记；M-11 Web 对比页（语义 / 文本两视图 + 并排 + 词级高亮）；M-07 噪声规则与聚类标签。
- **交**：打开页面即见默认对比；报告 JSON 含 `algo_version` 与稳定 `report_id`；20 处零散改动聚成 ≤ 5 条命名变更。

### 第 4 周｜10 月 25 日 – 11 月 1 日（打磨与交付验收）
- **做**：M-11 时间线视图（锚点 / 快照 / 注解）+ 三视图切换复用缓存；M-08 报告导出（Markdown / JSON）；M-13 `BehaviorDiffAdapter` 接口契约文档；验收用例集；非功能验收。
- **交**：报告可导出并粘贴 PR；接口契约文档 + 验收用例 + 验收报告。

## 三、你的验收标准

| 项 | 标准 |
| --- | --- |
| 默认对比 | 打开即得 Working vs Baseline，不需要选择对比对象 |
| 可读性 | 10 处实际语义修改，报告正确指出 ≥ 8 处 |
| 噪声比 | 报告中纯格式 / 重排条目 ≤ 10% |
| 聚类 | 20 处零散改动聚成 ≤ 5 条命名变更 |
| 可复现 | 同一对 Revision + 同一 `algo_version` → 报告逐字节相同（100%） |
| 性能 | L0 + L1 ≤ 200 毫秒；L2 ≤ 1.5 秒；L3 ≤ 3 秒；缓存命中 ≤ 100 毫秒 |
| 降级 | 解析失败自动回退到文本层，不报错、不阻断 |
| 总验收 | 改一次 Skill → 不做任何版本操作 → 看到语义级对比报告 → 可打锚点 → 可撤销 |
