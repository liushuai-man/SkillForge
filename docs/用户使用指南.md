# 留痕用户使用指南

留痕在本机监听 技能目录，保存文件后自动记录快照，在桌面客户端或网页中查看静态差异。它不运行技能、不调用 Codex、不自动评分。

## 1. 安装与启动

### 桌面日常使用

Windows 便携包保留完整目录，双击 **留痕.exe**；无需外装 Python/Node。后端、命令行和数据均在本机，窗口标题只显示“留痕”。随包命令行调用同一服务，例如 `skillforge-vm.cmd status`。安装器、签名、自动更新及其他平台尚未交付。

源码先在项目根执行 `uv sync`、`npm --prefix frontend ci`、`npm --prefix desktop ci`（Node.js 22.12+），之后双击 `start-desktop.cmd`。首次准备完成后不用重复安装。需要隔离试用时运行 `.\test.cmd desktop`，它自动分配全新测试数据根；默认日常入口仍复用原有历史。

关闭窗口进入托盘继续监听，双击托盘恢复；“应用→退出留痕”或托盘“退出”才结束。只停止客户端自己启动的服务，复用的已有服务继续运行。强杀可能留下陈旧 runtime，重新启动会检查并恢复，无需手动删除锁或数据。

### 自定义数据根与命令行

日常桌面与命令行默认共用数据根，命令行示例默认省略 `--data-root`。确需自定义时两端使用同一变量：

```powershell
$dataRoot = "D:\SkillForgeData"
.\start-desktop.cmd --data-root $dataRoot
# 客户端运行期间，在另一个终端使用同一路径：
uv run skillforge-vm --data-root $dataRoot status
```

安装包用户将 `uv run skillforge-vm` 换为随包 `skillforge-vm.cmd`。数据根必须位于被纳管技能目录之外。

### 开发、回归和发行验收

统一命令表与首次准备见 [README：测试与隔离试用](../README.md#测试与隔离试用)。`.\test.cmd` 执行自动回归；`desktop` 是手动桌面试用，`smoke` 是桌面自动验收，`experience` 是真实服务/命令行，`portable --bundle "包目录"` 验收指定便携包。桌面/便携模式自动生成新测试目录，可连续运行，不要传入真实技能作为测试材料。

`.\dev.cmd` 在浏览器中提供热更新，与桌面运行区分；开发数据为 `dist/dev/data`，连接它的命令行也须指定这个数据根。Ctrl+C 仅停止本次开发前后端。便携构建与验收的可复制命令以 README 为准，不自动覆盖旧包。

### 浏览器与 wheel 兼容入口

源码可双击 `start-web.cmd`，或执行 `uv run skillforge-vm gui`；默认在浏览器打开本机服务，关闭网页仍继续监听。发布 wheel 内置网页，但仍需 Python 3.11+、pipx 和可用依赖源/缓存。安装后执行 `skillforge-vm gui`。

用户界面是服务首页，默认 `http://127.0.0.1:8756/`；`/api/docs` 是开发者接口调试页。端口被占用会动态选择，实际地址记录在数据根 `runtime.json`。桌面和网页共用同一套接口与比较结果。

## 2. 纳管目录

顶部目录名称旁的 × 可关闭当前文件夹，回到欢迎页；后台纳管和历史保留。可从顶部列表重新打开，刷新列表不会自动重开刚关闭的目录。

开始页和已打开工作区侧栏的“打开文件夹”均直接打开系统目录选择窗口，选定后自动纳管。开始页主区也可展开“手动输入路径”；取消或失败后仍保留手动表单。关闭工作区后可点击“继续工作”重开已纳管目录，不重复创建工作区。

准备好含 `SKILL.md` 的目录，例如 `D:\skills\example`。从项目根目录另开终端执行：

```powershell
uv run skillforge-vm init D:\skills\example --name example
uv run skillforge-vm workspaces
```

Windows 网页用户点击“打开文件夹”，在系统目录选择窗口中选中 技能目录并确认后自动纳管；取消不纳管。也可展开“手动输入路径”，填写绝对路径和可选名称，再点击“纳管此目录”。自定义名称可在打开窗口前填写。系统窗口等待上限为 120 秒，失败提示原因并保留手动输入方式；其他系统当前使用手动输入。安装包终端用户省略 `uv run`。所有终端使用同一数据根；数据根必须在 技能目录之外。选择工作区并核对“监听目录”，列表可手动刷新。

压缩包必须先解压，再纳管解压目录。修改压缩包 不会更新这个目录，也不会自动成为新快照。复制 技能目录不包含数据根里的历史、锚点和对象库。

## 3. 保存、选版本、看文件

1. 在编辑器修改Skill并保存；服务自动记录，通常约500ms静默后开始捕获。不需要手动提交版本。
2. 打开页面直接看到最新两版的文件差异。顶部“旧版/新版”可直接选历史版本，“⇄”交换左右，“最新两版”回到自动更新。
3. 左侧点击变更文件；中央左旧右新，展示完整正文、真实行号、红删绿增和字符高亮。未修改内容保持对齐，不再显示语义、聚类或风险。
4. “上一处/下一处”或Shift+F7/F7跳转；可勾选“折叠未修改区域”。文件头显示换行格式、BOM和末尾无换行；二进制/超限明确说明，历史仍保留。
5. 左侧历史“查看此版改动”比较该版与上一版；也可勾选两个版本比较，或“与最新比较”。固定历史不会随新保存移动。
6. “标记版本”命名右侧版本。“恢复右侧版本…”或历史“恢复此版本”先预览清单，确认才回写；“撤销恢复”也先预览。普通纳管始终只读。

侧栏/底部面板可收起、调整；三主题保持。手动快照仅用于立即捕获或添加说明，不是保存流程的必需步骤。恢复未完成时继续原计划，状态区或“修订与续作”可重开；取消不继续回写。新保存和重连自动刷新默认比较，错误保留旧结果并提示重试。变更文件全文不是完整历史目录浏览器。

## 4. 标记版本与锚点

默认比较最新版本与上一个版本；只有首次纳管才与空内容比较。可以在界面“标记版本”输入名字，也可以执行：

```powershell
uv run skillforge-vm tag 已验证
uv run skillforge-vm tag 稳定版
```

“已验证”“稳定版”（以及旧的 `tested`、`stable`）是普通自定义名字，不会自动测试或认证。创建锚点默认先捕获当前磁盘内容，将命名引用和兼容保留引用指向该版本。锚点不会改变默认比较；需要时用 `diff --base 已验证` 或网页指定比较选择锚点。后续保存不移动锚点。只有人工测试通过的版本才建议命名为“已验证”。

## 5. 常用命令行

下列子命令均加上 `uv run skillforge-vm`；便携包用户使用随包 `skillforge-vm.cmd`；自定义数据根时与客户端保持一致。存在多个工作区时，对业务命令加 `--ws <工作区ID>`。

| 子命令 | 用途 |
| --- | --- |
| `status` | 当前修订、未捕获改动和待续作恢复计划 |
| `snapshot --message "说明"` | 手动捕获；无变化时不制造空快照 |
| `log` | 版本历史 |
| `show tested` | 修订元数据 JSON，不是文件全文 |
| `diff` | 最新与上一个版本的文件清单和Git风格上下文diff |
| `diff --summary` | 只列变更文件与增删行数 |
| `diff --base tested --head @` | 指定两个端点的静态对比 |
| `tag tested` | 创建或移动锚点，供显式比较或恢复 |
| `ops` | 操作日志 |
| `restore tested` | 保护当前内容、展示清单并确认后，恢复整个技能目录 |
| `undo` | 撤销最近一次恢复；再次 undo 会撤销这次撤销 |
| `restore --resume <计划ID>` | 恢复中断后继续原计划 |

恢复前先保存编辑器缓冲区并暂停写入。取消确认不回写文件，但预览可能先记录尚未捕获的当前内容。恢复后的新改动会阻止盲目撤销。`--yes` 供明确授权的自动化，日常使用保留预览确认。恢复不会删除历史；不支持部分文件、文件/目录类型转换或撤销锚点。

常用命令（安装包直接运行，源码前加 `uv run`）：

```powershell
skillforge-vm diff
skillforge-vm diff tested @
skillforge-vm diff @~2 @ --file SKILL.md
skillforge-vm diff --context 5
skillforge-vm diff --summary
```

diff默认有3行未修改上下文，`@@`表示真实旧/新行号，`-`删除、`+`新增，行首空格为未修改。一个位置版本表示与最新比较；也可用--base/--head，但不能混用。多个工作区时在Skill目录内运行会自动识别，否则--ws指定；所有命令使用相同服务数据根。

## 6. 一次完整示例

1. 启动服务并纳管目录，打开网页，核对实际监听路径。
2. 确认当前版本适合作为参考，创建 `tested` 锚点。
3. 修改 `SKILL.md` 中一条约束并保存，不执行版本命令。
4. 网页自动展示新版本对，点击文件查看左右完整正文与行级变化。
5. 执行 `status`、`log`、`diff --base tested --head @`，观察与网页相同的已提交版本。
6. 人工复测后创建新锚点，例如 `tested-v2`；如需恢复，在网页选择旧版本、核对清单后确认；撤销最近一次恢复可回到恢复前内容。

## 7. 当前能力和限制

已实现：目录纳管、监听快照、文件/行级比较、两侧完整正文与真实行号、CLI上下文patch、基础分页历史、标记版本、受控恢复和撤销。实际验证范围见 [交付检查记录](交付检查记录.md)。

未实现：完整快照文件浏览器、独立 Markdown 报告导出、ZIP 自动同步、测试会话/视频/日志证据关联、行为执行与自动评分、跨机器历史导入导出。不提供语义/风险/行为评分。只读全文接口现用于变更文件对比，尚不提供所有未改文件的目录浏览。

在 Codex 中人工复测 Skill 的步骤和结果模板见 [Codex Skill 版本测试指南](Codex%20Skill%20版本测试指南.md)。
