# SkillForge VM 用户使用指南

SkillForge VM 在本机监听 Skill 目录，保存文件后自动记录快照，在网页中查看静态差异。它不运行 Skill、不调用 Codex、不自动评分。

## 1. 安装与启动

发布包包含预构建网页，运行时无需 Node。安装需要 Python 3.11+、pipx，以及安装依赖所需的网络或缓存；wheel 不包含所有依赖。

```powershell
pipx install <wheel路径>
skillforge-vm --data-root D:\SkillForgeData start
```

打开服务实际地址的首页（默认 `http://127.0.0.1:8756/`）。`/api/docs` 是开发者接口调试页，显示 JSON 属正常行为，用户界面在首页。端口占用时服务选择其他端口，实际地址写在数据根的 `runtime.json` 中。

从源码开发时，在项目根目录的终端 A：

```powershell
uv sync
uv run skillforge-vm --data-root D:\SkillForgeData start
```

在终端 B 进入项目的 `frontend` 目录：

```powershell
npm ci
npm run dev
```

打开 Vite 输出的地址（通常为 `http://localhost:5173/`）。源码服务未内置网页时，后端首页返回 404，此时使用 Vite 地址。开发代理固定连接 `127.0.0.1:8756`，后端回退端口后需核对代理目标；发布包网页和 API 使用同一地址。

## 2. 纳管目录

准备好含 `SKILL.md` 的目录，例如 `D:\skills\example`。在终端 C（源码模式从项目根目录执行）：

```powershell
uv run skillforge-vm --data-root D:\SkillForgeData init D:\skills\example --name example
uv run skillforge-vm --data-root D:\SkillForgeData workspaces
```

安装包用户省略 `uv run`。所有终端使用同一数据根；数据根必须在 Skill 目录之外。纳管后刷新网页，选择工作区并核对“监听目录”。没有工作区时页面显示纳管命令。

ZIP 必须先解压，再纳管解压目录。修改 ZIP 不会更新这个目录，也不会自动成为新快照。复制 Skill 目录不包含数据根里的历史、锚点和对象库。

## 3. 自动快照与网页操作

1. 在编辑器修改已纳管目录中的文件并保存到磁盘。未保存的缓冲区不会被记录。
2. 监听器通常在约 500 ms 静默后合并捕获，扫描和报告计算还需时间；持续保存期间可能保持待处理状态。
3. 网页收到新快照通知后自动更新默认报告，无需手动快照或点击开始比较。更新期间标记旧结果；失败显示原因，可点击“刷新当前对比”重试。
4. 先看版本对、结论、风险和待确认数量，再展开语义分组中的前后证据。切换“原文差异”，从“变更文件”选择路径，查看只读并排片段。
5. 历史列表显示时间、触发原因、锚点和相对父版本的摘要。每页 20 项，页上界固定；新版本出现时点击“查看最新历史”，不会偷偷移动当前阅读位置。可以跨页勾选两个版本比较，或点击“与当前比较”。

原文视图展示的是**变更片段**，不能浏览快照全部文件或打开完整历史 `SKILL.md`。二进制、超限文件仍显示路径与降级原因。解析降级或没有语义分组，不等于没有变化；风险是静态规则提示，不是实际效果测试。

相同内容反复保存、只改 mtime 不生成空修订。A→B→A 是三次历史事件，即使首尾内容相同。停机期间改动会在服务重启后补获；网页断线重连后会重新读取报告。

## 4. stable / tested 基线

没有命名锚点时默认与空树比较，会看到全部纳管内容。可以在网页“建立基线”输入名字，也可以执行：

```powershell
uv run skillforge-vm --data-root D:\SkillForgeData tag tested
uv run skillforge-vm --data-root D:\SkillForgeData tag stable
```

`tested`、`stable` 是普通自定义名字，不会自动测试或认证。创建锚点默认先捕获当前磁盘内容，将命名引用和默认 Baseline 一起指向该版本。**最近创建或移动的命名锚点成为默认基线**，不会自动优先选择 stable；后续保存不移动锚点。只有人工测试通过的版本才建议命名为 tested。

## 5. 常用 CLI

下列子命令均加上 `uv run skillforge-vm --data-root D:\SkillForgeData`；安装包用户省略 `uv run`。存在多个工作区时，对业务命令加 `--ws <工作区ID>`。

| 子命令 | 用途 |
| --- | --- |
| `status` | 当前修订、未捕获改动和待续作恢复计划 |
| `snapshot --message "说明"` | 手动捕获；无变化时不制造空快照 |
| `log` | 版本历史 |
| `show tested` | 修订元数据 JSON，不是文件全文 |
| `diff` | 默认基线与当前版本的结论 |
| `diff --base tested --head @` | 指定两个端点的静态对比 |
| `tag tested` | 创建或移动锚点，并选为默认基线 |
| `ops` | 操作日志 |
| `restore tested` | 保护当前内容、展示清单并确认后，恢复整个 Skill |
| `undo` | 撤销最近一次恢复；再次 undo 会撤销这次撤销 |
| `restore --resume <计划ID>` | 恢复中断后继续原计划 |

恢复前先保存编辑器缓冲区并暂停写入。取消确认不回写文件，但预览可能先记录尚未捕获的当前内容。恢复后的新改动会阻止盲目撤销。`--yes` 供明确授权的自动化，日常使用保留预览确认。恢复不会删除历史；不支持部分文件、文件/目录类型转换或撤销锚点。

## 6. 一次完整示例

1. 启动服务并纳管目录，打开网页，核对实际监听路径。
2. 确认当前版本适合作为参考，创建 `tested` 锚点。
3. 修改 `SKILL.md` 中一条约束并保存，不执行版本命令。
4. 网页自动展示新版本对、变化结论和风险；展开证据或选择原文文件检查前后片段。
5. 执行 `status`、`log`、`diff --base tested --head @`，观察与网页相同的已提交版本。
6. 人工复测后创建新锚点，例如 `tested-v2`；如需恢复，在网页选择旧版本、核对清单后确认；撤销最近一次恢复可回到恢复前内容。

## 7. 当前能力和限制

已实现：目录纳管、监听快照、静态 L0～L3 对比、规范 JSON 报告、语义结论、只读片段、基础分页历史、锚点、受控恢复和撤销。实际验证范围见 [交付检查记录](交付检查记录.md)。

未实现：完整快照文件浏览器、独立 Markdown 报告导出、ZIP 自动同步、测试会话/视频/日志证据关联、行为执行与自动评分、跨机器历史导入导出。M-13 仅有类型契约，报告 `behavior=null`。完整文件浏览需先定义只读列表/正文接口及文本、二进制、路径与对象损坏边界；其余扩展项不因 issue 描述而默认为已实现。

在 Codex 中人工复测 Skill 的步骤和结果模板见 [Codex Skill 版本测试指南](Codex%20Skill%20版本测试指南.md)。
