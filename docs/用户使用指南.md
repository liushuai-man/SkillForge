# SkillForge VM 用户使用指南

SkillForge VM 在本机监听 Skill 目录，保存文件后自动记录快照，在桌面客户端或网页中查看静态差异。它不运行 Skill、不调用 Codex、不自动评分。

## 1. 安装与启动

Windows 便携包通过 `uv run python scripts/build_desktop.py --output dist/desktop/SkillForge-VM` 构建，目标必须为新目录；解压/复制完整目录后双击 `SkillForge-VM.exe`，无需外装 Python/Node。随包 `skillforge-vm.cmd --data-root D:\SkillForgeData status` 调用同一本机服务。现有 wheel 发布方式仍需 Python/pipx，不能将它等同于桌面便携包。

Electron 桌面入口：源码先 `uv sync`、`npm --prefix desktop ci`（Node >=22.12）和 `npm --prefix frontend run build`，再双击 `start-desktop.cmd`；指定数据目录可执行 `npm --prefix desktop start -- --data-root D:\SkillForgeData`。默认与 CLI 共用原数据根，界面在独立窗口中打开，不启动外部浏览器。


关闭桌面窗口进入托盘继续监听，双击托盘恢复窗口；托盘“退出”或“应用→退出 SkillForge VM”才退出。仅停止桌面自己运行的服务，已有 CLI/网页服务继续运行；异常退出通过父进程监控及管道断开触发自有服务清理。强杀可能留下陈旧 runtime 运行记录，重新启动会检查服务并恢复，不需要手动删除锁或数据。重复打开聚焦同一窗口；启动失败按错误提示处理后重开。安装器/自动升级/开机启动/其他平台不在本轮。

开发环境统一在项目根运行 `.\dev.cmd`：准备前端依赖、启动独立数据根 `dist/dev/data` 的 API 和 Vite，并打开 `http://127.0.0.1:5173/`。代理使用实际 API 端口；Ctrl+C 停止本次启动的前后端。前端热更新，后端修改后重新运行。测试 Skill 默认位于仓库同级 `Mytest/skillForge-testskills`，本机为 `D:\mycode\Mytest\skillForge-testskills`。

Windows 源码用户可直接双击项目根的 `start-web.cmd`，或运行 `uv run skillforge-vm gui`。启动器准备已有依赖与网页构建、启动后台服务并打开浏览器；源码首次构建需 uv 和 Node.js/npm。安装包用户安装后运行 `skillforge-vm gui`，或双击发布目录附带的 `start-web.cmd`，运行网页无需 Node。已有同数据根服务会复用；关闭网页不停止后台监听，日志位于数据根 `gui-launch.log`。

以下手动启动及前端热更新命令供终端使用与开发选择；日常网页使用不必同时开启三个终端。

发布包包含预构建网页，运行时无需 Node。安装需要 Python 3.11+、pipx，以及安装依赖所需的网络或缓存；wheel 不包含所有依赖。

```powershell
pipx install <wheel路径>
skillforge-vm --data-root D:\SkillForgeData start
```

打开服务实际地址的首页（默认 `http://127.0.0.1:8756/`）。`/api/docs` 是开发者接口调试页，显示 JSON 属正常行为，用户界面在首页。端口占用时服务选择其他端口，实际地址写在数据根的 `runtime.json` 中。

从源码开发时，在项目根目录的终端 A：

```powershell
uv sync
uv run skillforge-vm --data-root D:\SkillForgeData start
```

在终端 B 进入项目的 `frontend` 目录：

```powershell
npm ci
npm run dev
```

打开 Vite 输出的地址（通常为 `http://localhost:5173/`）。源码的 `frontend/dist` 已构建时也可由后端首页托管；未构建时使用 Vite 地址。单独启动 Vite 时代理默认连接 `127.0.0.1:8756`，可用 `SKILLFORGE_DEV_API_URL` 指定；统一 `dev.cmd` 自动传入实际后端地址。发布包网页和 API 使用同一地址。

## 2. 纳管目录

顶部目录名称旁的 × 可关闭当前文件夹，回到欢迎页；后台纳管和历史保留。可从顶部列表重新打开，刷新列表不会自动重开刚关闭的目录。

欢迎页的“添加 Skill 目录”和侧栏“打开文件夹”均直接打开系统目录选择窗口，选定后自动纳管，不必先展开侧栏再点一次。

准备好含 `SKILL.md` 的目录，例如 `D:\skills\example`。在终端 C（源码模式从项目根目录执行）：

```powershell
uv run skillforge-vm --data-root D:\SkillForgeData init D:\skills\example --name example
uv run skillforge-vm --data-root D:\SkillForgeData workspaces
```

Windows 网页用户点击“打开文件夹”，在系统目录选择窗口中选中 Skill 目录并确认后自动纳管；取消不纳管。也可展开“手动输入路径”，填写绝对路径和可选名称，再点击“纳管此目录”。自定义名称可在打开窗口前填写。系统窗口等待上限为 120 秒，失败提示原因并保留手动输入方式；其他系统当前使用手动输入。安装包终端用户省略 `uv run`。所有终端使用同一数据根；数据根必须在 Skill 目录之外。选择工作区并核对“监听目录”，列表可手动刷新。

ZIP 必须先解压，再纳管解压目录。修改 ZIP 不会更新这个目录，也不会自动成为新快照。复制 Skill 目录不包含数据根里的历史、锚点和对象库。

## 3. 保存、选版本、看文件

1. 在编辑器修改Skill并保存；服务自动记录，通常约500ms静默后开始捕获。不需要手动提交版本。
2. 打开页面直接看到最新两版的文件差异。顶部“旧版/新版”可直接选历史版本，“⇄”交换左右，“最新两版”回到自动更新。
3. 左侧点击变更文件；中央左旧右新，展示完整正文、真实行号、红删绿增和字符高亮。未修改内容保持对齐，不再显示语义、聚类或风险。
4. “上一处/下一处”或Shift+F7/F7跳转；可勾选“折叠未修改区域”。文件头显示换行格式、BOM和末尾无换行；二进制/超限明确说明，历史仍保留。
5. 左侧历史“查看此版改动”比较该版与上一版；也可勾选两个版本比较，或“与最新比较”。固定历史不会随新保存移动。
6. “标记版本”命名右侧版本。“恢复右侧版本…”或历史“恢复此版本”先预览清单，确认才回写；“撤销恢复”也先预览。普通纳管始终只读。

侧栏/底部面板可收起、调整；三主题保持。手动快照仅用于立即捕获或添加说明，不是保存流程的必需步骤。恢复未完成时继续原计划，状态区或“修订与续作”可重开；取消不继续回写。新保存和重连自动刷新默认比较，错误保留旧结果并提示重试。变更文件全文不是完整历史目录浏览器。

## 4. stable / tested 基线

默认比较最新版本与上一个版本；只有首次纳管才与空内容比较。可以在网页“建立基线”输入名字，也可以执行：

```powershell
uv run skillforge-vm --data-root D:\SkillForgeData tag tested
uv run skillforge-vm --data-root D:\SkillForgeData tag stable
```

`tested`、`stable` 是普通自定义名字，不会自动测试或认证。创建锚点默认先捕获当前磁盘内容，将命名引用和兼容保留引用指向该版本。锚点不会改变默认比较；需要时用 `diff --base tested` 或网页指定比较选择锚点。后续保存不移动锚点。只有人工测试通过的版本才建议命名为 tested。

## 5. 常用 CLI

下列子命令均加上 `uv run skillforge-vm --data-root D:\SkillForgeData`；安装包用户省略 `uv run`。存在多个工作区时，对业务命令加 `--ws <工作区ID>`。

| 子命令 | 用途 |
| --- | --- |
| `status` | 当前修订、未捕获改动和待续作恢复计划 |
| `snapshot --message "说明"` | 手动捕获；无变化时不制造空快照 |
| `log` | 版本历史 |
| `show tested` | 修订元数据 JSON，不是文件全文 |
| `diff` | 最新与上一个版本的文件清单和Git风格上下文diff |
| `diff --summary` | 只列变更文件与增删行数 |
| `diff --base tested --head @` | 指定两个端点的静态对比 |
| `tag tested` | 创建或移动锚点，供显式比较或恢复 |
| `ops` | 操作日志 |
| `restore tested` | 保护当前内容、展示清单并确认后，恢复整个 Skill |
| `undo` | 撤销最近一次恢复；再次 undo 会撤销这次撤销 |
| `restore --resume <计划ID>` | 恢复中断后继续原计划 |

恢复前先保存编辑器缓冲区并暂停写入。取消确认不回写文件，但预览可能先记录尚未捕获的当前内容。恢复后的新改动会阻止盲目撤销。`--yes` 供明确授权的自动化，日常使用保留预览确认。恢复不会删除历史；不支持部分文件、文件/目录类型转换或撤销锚点。

常用命令（安装包直接运行，源码前加 `uv run`）：

```powershell
skillforge-vm diff
skillforge-vm diff tested @
skillforge-vm diff @~2 @ --file SKILL.md
skillforge-vm diff --context 5
skillforge-vm diff --summary
```

diff默认有3行未修改上下文，`@@`表示真实旧/新行号，`-`删除、`+`新增，行首空格为未修改。一个位置版本表示与最新比较；也可用--base/--head，但不能混用。多个工作区时在Skill目录内运行会自动识别，否则--ws指定；所有命令使用相同服务数据根。

## 6. 一次完整示例

1. 启动服务并纳管目录，打开网页，核对实际监听路径。
2. 确认当前版本适合作为参考，创建 `tested` 锚点。
3. 修改 `SKILL.md` 中一条约束并保存，不执行版本命令。
4. 网页自动展示新版本对，点击文件查看左右完整正文与行级变化。
5. 执行 `status`、`log`、`diff --base tested --head @`，观察与网页相同的已提交版本。
6. 人工复测后创建新锚点，例如 `tested-v2`；如需恢复，在网页选择旧版本、核对清单后确认；撤销最近一次恢复可回到恢复前内容。

## 7. 当前能力和限制

已实现：目录纳管、监听快照、文件/行级比较、两侧完整正文与真实行号、CLI上下文patch、基础分页历史、标记版本、受控恢复和撤销。实际验证范围见 [交付检查记录](交付检查记录.md)。

未实现：完整快照文件浏览器、独立 Markdown 报告导出、ZIP 自动同步、测试会话/视频/日志证据关联、行为执行与自动评分、跨机器历史导入导出。不提供语义/风险/行为评分。只读全文接口现用于变更文件对比，尚不提供所有未改文件的目录浏览。

在 Codex 中人工复测 Skill 的步骤和结果模板见 [Codex Skill 版本测试指南](Codex%20Skill%20版本测试指南.md)。
