# SkillForge 版本管理器 · 实现契约与验收

> 版本：v0.1，2026-10-08。本文规定后续实现的交接边界与验收证据，**不是当前实现能力清单**。
> 产品范围、需求与设计取舍以[设计文档](./SkillForge%20版本管理器设计文档.md)为准；排期见[分工与交付计划](./SkillForge%20版本管理器分工与交付计划.md)。本文不另设第二套产品需求。
> “已定”表示可以据此实现；“待决”表示相关任务不能靠猜测开工。本文新增要求不会自动改变已有数据格式或迁移数据库。

## 1. 模块交接与单一真值

### 1.1 数据归属

| 数据 / 能力 | 维护方 | 消费方式 |
| --- | --- | --- |
| 工作区配置、路径与忽略规则 | A / M-01 | 读取不可变的有效配置快照；其他模块不重写 workspace.json |
| 对象编码、读写、完整性 | A / M-03 | 通过对象库公开接口读取原始 bytes；消费者不自行拼存储路径 |
| Revision、Change、Ref、路径索引 | A / M-04 | 解析引用、获取修订、列历史；M-05 不直查 revision/ref 表 |
| Op 与操作前后状态 | A / M-09 | 业务提交入口组织事务；路由与 CLI 不拼 SQL |
| 文件差异与分层缓存 | B / M-05 | 以不可变 Revision 对和固定分析配置为输入 |
| 结构解析、语义单元 | B / M-06 | 接收内容/路径/配置并返回纯数据；不读数据库、不自行访问 Skill 根 |
| 聚类 | B / M-07 | 接收变更单元；保留其 ID 与证据，不重读文件 |
| 规范报告与报告存储 | B / M-08 | 接收 M-05 结果，组装规范报告；不自行解析或读取对象库 |
| HTTP / CLI / UI | A / M-10、M-12；B / M-11 | HTTP 是共同入口；UI/CLI 不重新实现 diff、ref 解析或结论规则 |
| SQLite 连接与物理 DDL | A / db | 提供连接/事务基础；表内操作由对应模块封装，不能变成任意模块的 SQL 通道 |

不得为每个调用再建一套近似 DTO。公共 Pydantic 模型放在数据拥有模块的公开模型文件；通用 ID/枚举可放 core。`__init__.py` 存在不等于公开接口已实现。

### 1.2 两线交接最小包

跨模块实现开始前，提供并由消费方核对以下内容（可放在任务描述/PR，不强制新建文档）：

1. 一个公开入口及其输入/输出模型，字段类型、必填/可空、默认值、枚举与排序规则。
2. 一组正常、空结果、失败/降级样例，使用同一份 schema 校验；示意图中的缩写 ID 不可用作真实测试 ID。
3. 该调用会修改什么状态，事务/提交边界是什么；失败后能否重试、有何幂等性。
4. 提供方与消费方共用的契约用例。假数据必须符合此模型，不得先各写一套字段再联调。

仅内部重构且公开行为不变时，不重复走协议确认。对象格式、DDL、错误码、公共字段、状态语义变化必须先更新权威章节，给出兼容影响；不能靠前端临时兼容字段名掩盖分歧。

## 2. 状态与提交边界

### 2.1 工作区初始化

- 准备中的工作区不出现在正常列表。所有对象、数据库与配置完成后才发布可见标志；发布失败也属于初始化失败。
- 失败清理只处理本次创建、位于独立数据根内的临时产物，绝不能删除 Skill 文件或其他有效工作区。也可保留可识别的中断产物供恢复，但再次 init 必须能安全重试。
- 同一路径重复成功 init 报 `workspace_already_initialized`；先前失败不应占住该路径。单个损坏工作区给出明确诊断，不应让其他有效工作区无法列出。
- 规范路径按实际平台大小写规则比较；拒绝数据路径等于或位于 Skill 根内。内部扫描路径使用根内相对路径；拒绝越界、绝对路径和 `..`，不跟随符号链接/junction。

### 2.2 快照、引用与操作

| 情况 | 必须发生 | 不能发生 |
| --- | --- | --- |
| 仅 mtime 变化，tree 与当前相同 | 返回当前 Revision，created=false | 新对象、新 Revision、Op、seq、元数据时间戳写入 |
| 原始内容/路径改变 | 先写对象，再同事务提交索引、Revision、Change、状态/Op，created=true | 数据库提交前发布成功事件 |
| A→B→A | 第三步创建新 Revision，复用 A 的 blob/tree | 跳回旧 Revision 并抹掉这次变化事件 |
| 无锚点 | 默认比较 base=null 与捕获到的 head | 自动创建 stable 或空 Revision 数据行 |
| 用户打锚点 | 先取得当前稳定 Revision，再同事务移动 ref 与选中 Baseline、记录 Op | 保存文件时自动推进用户 Baseline |
| 引用在计算中移动 | 本次报告仍使用入队时固定的 Revision 对 | 一个报告混用新旧基线 |
| 数据库提交失败 | 不公布新状态；允许留下未引用对象供重试 | 清理已经被其他已提交历史引用的对象 |
| 进程强杀后重启 | 识别未发布初始化/临时对象，重扫工作区，保持已提交状态 | 把“有对象文件”当作“快照已提交” |

`@` 的捕获和锚点操作复用同一个串行快照入口。并行对比只读已提交内容。业务事务不得嵌套各自 commit；SQLite 外键约束不会自动补足文件系统一致性。无变化“零写入”指对象与业务元数据，诊断日志单列测量；不能用日志写入伪装成 Revision 更新。

### 2.3 撤销：明确待决边界

**TBD-08 待用户决定**：现行约束禁止向 Skill 目录写文件。因此，在该项关闭前，`undo/restore` 只能讨论版本库状态补偿，不能实现文件回写，也不能向用户宣称编辑器中的内容已经恢复。禁止通过改写“不入侵”的措辞偷偷取得文件写入授权。

**TBD-09 待 A 定稿、B 校验**：现有 DDL 尚未完整定义运行状态。实现 M-04/M-09 的状态写入前，必须为下表补齐唯一持久化载体、原子更新方式、重启读取规则及 before/after 序列化样例：

| 状态 | 必须回答的问题 |
| --- | --- |
| 当前已提交 Revision | 与 last（最大 seq）及物理文件状态是否相同；撤销后如何显示/重新扫描 |
| 当前 Baseline | 保存选中的 ref 名还是固定 Revision；同名 ref 更新/撤销后如何解析 |
| 活动 Change | 空闲、打标、重启、撤销边界如何一致判断；不制造空 Change |
| 当前 Op | 撤销针对哪个操作；自动快照是否是撤销目标；如何区分补偿与删除历史 |
| Op payload | 各 kind 的必填 before/after、引用内容及格式版本；重试与重复提交如何处理 |

若需要 DDL 变化，先按 AGENTS 的兼容流程决定，再改 schema，不能往 config_json 临时塞未约定状态。以上待决项不阻塞对象库、纯 diff 与语义样例，但**会阻塞完整“可撤销”验收**。不能仅删除待决标记而没有决策内容。

## 3. 对比输入、证据与报告

### 3.1 不可变输入与可复现身份

- 比较输入：`base_rev: str|null`、`head_rev: str`、`layer: L0|L1|L2|L3`、有效 `algo_version`。base=null 唯一表示空树，head 必须是已提交 Revision，且双方属于同一工作区。
- 默认 layer=L3。每项任务开始时固定解析映射、规则/模板/噪声配置，不在处理中再次读取可变配置文件。
- `algo_version` 包含算法、规则、解析器/语法库、报告 schema 版本和有效分析配置指纹；影响结果的配置不能遗漏。数据目录、端口、日志级别等不影响结果的配置不入指纹。
- `report_id = "RPT-" + SHA256(canonical_json([base_rev, head_rev, layer, algo_version]))`。canonical_json 的字节规则与设计 §7.7 相同。
- 位置指向原始 blob，不指向规范化后的字符串。后续开发前用 BOM、CRLF、中文及 emoji 固定样例验证索引映射。

### 3.2 语义变更最小交换结构

| 字段 | 类型 / 规则 |
| --- | --- |
| id | 稳定字符串；由 path/kind/op/两侧位置与内容的规范编码确定派生，不用随机 UUID |
| path | 主展示路径，根内相对路径，统一 `/`；移动时取 after.path，否则取存在一侧 |
| kind | 设计 §3.2 的八类枚举；不得让 UI 自增第九类 |
| op | `add|delete|modify|move`；模糊匹配不凭低置信度直接定为 move |
| before / after | 各为 null 或 SourceSpan；新增 before=null，删除 after=null，修改/移动两侧均有值 |
| rule_id | 判定规则的稳定版本标识，用于追溯；不能将提示词标签当规则依据 |

SourceSpan 固定为 `{path, start_byte, end_byte, text}`，偏移从 0 开始，区间为 `[start_byte,end_byte)`，基于原始 UTF-8 字节。text 与该区间解码一致；语义 span 不包含文件首 BOM，但偏移仍从含 BOM 的原始 blob 起算（首字符从字节 3 开始）。展示行号/列号由 UI 从源文本转换，不把 tree-sitter 字节列误当 JavaScript UTF-16 列。

非 UTF-8/二进制文件不强行 replacement decode 后给出语义结论，止于 L0 并说明原因。重命名时两侧 SourceSpan 可以是不同路径；先实现同内容一对一移动检测，歧义候选保留原始新增/删除证据并标待确认。相似度阈值和匹配决胜规则随 algo_version 与固定样例一起冻结，不可藏在 UI。

### 3.3 报告正文

- 顶层：`schema_version, report_id, algo_version, layer, base, head, overview, clusters, layers, needs_review, degraded, behavior`，形状见设计 §4.5。
- `base.rev=null` 表示零基线；ref 名、请求 ID、生成时刻和耗时不进入正文。`head.change_id` 来自不可变修订元数据。
- layers 固定含 metadata/structure/text/semantic；每层 status 为 `not_requested|computed|degraded`。computed+空列表才表示该层已计算且无差异；较低层请求不得伪造 semantic.computed。
- metadata.files 保留各变化文件及 `add|delete|modify|move` 类型；文本 hunks/结构 nodes 的扩展 schema 在相应层开工前由 B 给出合法样例并让 UI 校验，不得让两个消费者各自定义坐标。
- 语义层 units 使用 §3.2；clusters.units 的每个 ID 和 needs_review.unit 的非空 ID 必须能解析到实际单元。无法归类的疑点可用 `{unit:null,path,reason_code}` 表达，不虚构单元。
- degraded 使用稳定 `{path,requested_layer,available_layer,reason_code}`。非文本/超过上限止于 L0，解析失败降到 L1；因一个文件降级不能跳过其他文件。
- overview.files 按变化文件去重；overview.changes 计聚类前语义变更数（未计算时为 null）；overview.clusters 等于 clusters 长度。risk 只能来自有版本的规则映射，不用随机置信度或模型猜值；不能判定时为 unknown。
- 列表按相对路径 UTF-8、类型、位置、ID 排序，所有并列情况有稳定决胜。模板、规则和序列化变化必须更新有效算法版本。
- behavior 在 MVP 固定为 null，界面明确“未接入行为对比”；不要注册成功的占位执行接口。

样例 JSON、Pydantic 验证、TypeScript 消费样例必须交叉校验字段/空值/枚举。文档中的说明性骨架不代替可执行 schema，也不允许照抄不存在的 uXX 引用。

## 4. HTTP、错误与事件

### 4.1 返回与默认值

- 路由前缀 `/api`；默认只监听 loopback。CLI 的 start 是启动服务入口，其他业务命令只调用服务；服务未启动时给出启动提示，不能偷偷直读数据库。
- 成功：`{ok:true,data:...,error:null,request_id:"..."}`；失败：`{ok:false,data:null,error:{code,message,detail},request_id:"..."}`。detail 为 string|null，message 解释具体问题。
- 请求字段验证错误也使用统一外壳；不得泄漏框架默认的另一套错误 JSON。真实未知异常不假冒 object_not_found 等已知原因；以 request_id 关联本地日志，明确说明失败操作。
- diff 的 base/head 省略才使用默认基线/@；显式空字符串、未知引用、错误 layer 报参数/引用错误，不能默默回退。状态接口明确区分处理中、就绪、降级、失败；旧报告只能带明确的旧 head 标记展示。
- 列表按稳定 seq/ID 使用游标；请求处理期间固定上界，不能因后续保存导致一页内顺序漂移。
- 每个 POST 在实现前声明重试语义。MVP 不承诺所有 POST 幂等；连接中断后先查询状态核对结果，客户端不得盲目重发 undo。

### 4.2 错误分类

以下前七项已有 core 错误类型；HTTP 映射为目标契约，尚未代表路由实现。新增错误码必须在此登记并与消费方对齐。

| code | HTTP | 意义 / 处理 |
| --- | --- | --- |
| invalid_skill_root | 400 | 路径无效、不是目录或不满足纳管边界 |
| workspace_already_initialized | 409 | 已有成功初始化；返回已有工作区信息可供定位 |
| workspace_not_found | 404 | 工作区标识不存在 |
| workspace_data_missing | 409 | 已登记工作区的数据缺失/不完整，需要恢复 |
| object_store_not_writable | 507 | 对象存储不可写，停止提交并给出本地具体原因 |
| object_not_found | 409 | 有效历史引用的对象缺失，不能完成对比 |
| object_corrupted | 409 | 解压、头部、长度或 SHA-256 不匹配；停止本次报告 |
| invalid_request（目标） | 422 | 参数类型、枚举、OID 语法或区间无效 |
| ref_not_found / revision_not_found（目标） | 404 | 显式引用或修订不存在；不得替换成零基线 |
| snapshot_unstable（目标） | 409 | 工作区持续变化导致本次无法捕获稳定内容，可重试 |
| workspace_busy（目标） | 409 | 工作区/数据根已被另一服务写入，不启动第二写通道 |
| operation_failed（目标） | 500 | 未归类异常；说明失败步骤与日志 request_id，不编造底层原因 |

`parse_failed / unsupported_encoding / text_limit_exceeded / unsupported_file_type` 是诊断 reason_code，不是整个 HTTP 请求失败码。只有内容不受支持/语法问题可降级；权限拒绝、磁盘满、对象缺失/损坏必须作为失败处理。

### 4.3 事件

- 事件只在相应状态提交后发出。最低数据为 workspace_id 加 revision_id 或 report_id；消费者随后查询权威状态/报告。
- `snapshot/created` 指已提交 Revision；`diff/ready` 指完整规范报告已可取（可包含明确的逐文件降级）；`parse/degraded` 是补充通知。
- SSE 不保证历史重放或恰好一次；客户端断线重连、收到重复或乱序通知后，以 Revision seq 和当前请求身份判定，不让旧报告覆盖新报告。
- API 请求的 request_id、事件传输 ID 与 report_id 不混用；运行时通知时间不进入规范报告正文。

## 5. 验收矩阵与证据

以下是后续代码任务必须落地的行为用例，当前文档编辑不创建测试代码。使用测试专用临时 Skill 与独立数据目录，禁止在真实用户 Skill 上制造故障。

| ID | 输入 / 故障 | 必须观察到的结果 | 负责方 |
| --- | --- | --- | --- |
| AC-01 | 初始化时文件读取/对象写入/数据库提交任一失败，再重试 | 不出现伪成功工作区；成功重试；Skill 文件逐字节不变 | A |
| AC-02 | 同内容不同文件、不同条目插入顺序 | blob 去重，tree OID 顺序无关，字节读回一致 | A |
| AC-03 | 截断压缩对象、改头部/长度、替换为另一个合法压缩对象 | 缺失与损坏错误可区分；不返回错误原文或缓存空报告 | A |
| AC-04 | 相同内容保存 5 次 / 仅改 mtime | 0 新对象/Revision/Op，无业务数据库更新 | A |
| AC-05 | 500 ms 内有限突发保存 5 次后静默 | 最终稳定内容只提交一次；持续写入显示待处理，最终稳定后不漏记 | A |
| AC-06 | A→B→A，含手工回滚目录 | 三个修订事件按 seq 排序，首尾 tree 相同、rev_id 不同 | A |
| AC-07 | LF↔CRLF、BOM、中文/emoji、Markdown 双空格、YAML 缩进 | 原始字节不丢；格式折叠与有效语义变化分开；定位可回到正确字节 | A/B |
| AC-08 | 无基线 / 打 tested / 再保存 / 显式请求不存在的 stable | 空树回退；基线选中 tested；保存不移动基线；显式缺失报错 | A/B |
| AC-09 | 引用移动或配置更新与对比同时发生 | 单次任务输入固定；新配置形成新算法键；旧报告不变 | A/B |
| AC-10 | 八类单元增删改移；否定词、流程顺序、数组顺序；示例中的指令 | 与人工标注匹配；有证据；不把重要变化折叠成噪声 | B |
| AC-11 | 单个坏 YAML / 非 UTF-8 / 超过文本上限，与正常文件混合 | 按文件降级；明确层状态；其他文件继续；不声称全部无变化 | B |
| AC-12 | 无差异、未请求语义层、存在歧义三个样例 | 分别显示无差异/not_requested/needs_review，不混用空数组 | B |
| AC-13 | 同输入清空缓存后重算，打乱枚举顺序、重启进程 | 规范报告逐字节一致；ID、排序、引用均有效 | B |
| AC-14 | 20 处改动人工标为 ≤5 个意图，另有互不相关样例 | 前者 ≤5 组且不丢证据；后者不能强行合并凑指标 | B |
| AC-15 | 提交前后各故障点强杀进程后重启 | 无可见半快照；已提交状态可读；未完成操作可安全恢复 | A |
| AC-16 | 符号链接/junction、越界路径、数据根位于 Skill 内 | 不越界读写，不循环扫描；给出具体诊断 | A |
| AC-17 | SSE 重复/乱序/断线，CLI 与网页请求同一对比 | 重连重取状态；旧结果不覆盖新结果；规范报告相同 | A/B |
| AC-18 | undo→undo、重启、请求中断重试 | 按已关闭 TBD-08/09 的状态样例恢复；不丢历史；未关闭不能验收 | A/B |

### 5.1 语义质量样例口径

- 样例固定包含 before/after 文件、人工标注的 kind/op/证据位置/是否顺序敏感/意图分组。先冻结预期，再实现规则；增加新行为时追加样例，不能为迎合实现修改旧标注。
- 正确识别率 = 正确匹配的人工标注变更数 / 人工标注变更总数，聚类前计算，目标 ≥80%。同一真实变化重复报多次不能重复计分，多出的条目计误报。
- 噪声比 = 主结论中的纯格式/已证实无语义影响的重排条目数 / 主结论条目总数，目标 ≤10%；总数为 0 时记 0，并单独检查漏报。纯格式样例不得产生肯定的语义变更结论。
- 误报数/类型单独报告。否定词、流程顺序与示例误分类作为必须通过的回归样例，不能用全局 80% 平均值掩盖这些已知关键错误。
- 保存样例来源与脱敏方式；不得默认上传真实 Skill，不能为测试而引入外部模型。

### 5.2 交付证据

每个实现任务只选相关 AC，不要求每次跑完整套件。报告：关联需求/AC、运行命令、结果、未运行原因、文档更新及剩余待决项。存储/事务变更须测失败路径；算法变更须测无缓存重算；接口变更须测真实消费模型，不能只测自己构造的字典。

性能记录机器/系统、存储介质、文件数/字节数、算法与配置、缓存条件；至少给出 30 次重复的 p50/p95，目标按 p95 核对。运行受环境限制时标未验证，不以减少样例规模、禁用解析器或使用热缓存冒充目标通过。Python 3.11+ 的兼容性与 Windows/macOS/Linux 三平台分别给证据，未执行的平台不得宣称已验证。
